# Bug hunt — 21 November 2026

Scope: the 87-tool registry, the agent loop, the permission surface and the test
suite. Eight real defects were found and fixed; two of them were introduced by
this same session's work and caught before the push. The suite went from
**21 failed files / 28 failed tests** to **0 failed**.

The owner expected 10–15 bugs. Eight is the honest count: the rest of the red
was one environment effect (below), not fifteen separate faults.

## Fixed

1. **`.gitignore` did not actually ignore the build and cache directories.**
   It listed `node_modules` and `dist` without the trailing slash and had no
   `__pycache__/` or `.vite/` entry, so `git add -A` could stage build output
   and Python caches. Rewritten with the exact patterns the hygiene test pins.

2. **21 durability test files were red for a reason that says nothing about the
   code.** They make the memory file read-only (`chmod 444`) and expect the
   write to fail. Running as root, `chmod` does not stop a write, so every
   assertion inverted. They now `describe.skipIf(process.getuid?.() === 0)`
   with the reason written above the guard, instead of failing misleadingly.

3. **No consent layer at all.** Any prompt could reach `write_file`, `bash` or
   the network. `executeTool` now checks a stored capability grant first and
   returns a plain-language question instead of acting. See `docs/PERMISSIONS.md`.

4. **`ask_clarifying_questions` was mapped to the `platform` capability**, so a
   pure text formatter demanded permission to use Base44. It is now free.

5. **`selftest` would have reported `permission_required` for its own checks**
   after the gate landed. It now grants what it needs inside a throwaway
   permission store and restores the real one, so a selftest never widens the
   owner's grants. (Introduced and fixed in this session.)

6. **Two existing suites broke under the new gate** (`superAgent`, `toolParity`)
   because they call tools directly. Both now grant in their own temp store, so
   they test the tool, not the consent UI. (Introduced and fixed in this session.)

7. **No offline switch.** Network tools had no way to say "you are offline".
   `AGENT_OFFLINE=1` now refuses network/platform/calls/messages/publish with a
   precise reason while files, shell and memory keep working.

8. **The audit script itself asserted the wrong `write_file` output** and flagged
   a working tool as broken. Fixed, and the audit now grants all capabilities in
   a throwaway store so it measures tools rather than consent.

## Added

- `scripts/audit-tools.mjs` — validates all 87 schemas, resolves every legacy
  alias, runs the native tools for real, and fails if an unconfigured tool
  claims success. Current result: `advertised: 87 | bugs: 0`.
- `src/agent/permissions.ts` + `src/tests/permissions.test.ts` (10 tests).
- `docs/PERMISSIONS.md`.

## Known limits, stated plainly

- The 76 Base44 bridge tools and the 2 OpenAI-backed tools cannot work with no
  key: they need `BASE44_*` or `OPENAI_API_KEY`. Offline they answer
  `not_configured` and name the variable. Everything local works with no key.
- The durability suite only exercises its failure path on a non-root machine.
  On a root box it is skipped, not silently passed.
